# json_utko_generator

Утилита для преобразования Excel-таблиц в JSON маршрутов объектов учёта твёрдых коммунальных отходов (ФГИС УТКО).

Читает выгрузку с данными о населённых пунктах, объектах размещения/обработки/утилизации и параметрах движения, формирует вложенную структуру маршрутов (1 → 2 → 3 плечо) и сохраняет её в файл. Распространяется одним исполняемым файлом, установка дополнительного ПО не требуется.

## Возможности

- построение цепочки маршрутов: населённый пункт → объект 1 → объект 2 → объект 3;
- определение типа объекта по русскому названию из таблицы;
- расчёт времени в пути `TravelTime = Distance / Speed` с округлением до 2 знаков и защитой от деления на ноль;
- потоковое чтение листа: файл на десятки тысяч строк обрабатывается без роста потребления памяти;
- чтение точных значений ячеек — координаты и расстояния не теряют знаки из-за формата отображения;
- три режима работы: интерактивный, командная строка, пакетная обработка папки;
- пропуск проблемных строк с указанием номера строки Excel, обработка при этом продолжается.

## Требования

- Windows 10/11 (или Linux/macOS при сборке под свою систему);
- входные файлы в формате `.xlsx` (`.xls` не поддерживается);
- для сборки из исходников: Go 1.27+ и `github.com/xuri/excelize/v2 v2.11.1` — версии уже зафиксированы в `go.mod` и `go.sum`.

## Сборка

```bash
go mod download
go build -trimpath -ldflags="-s -w" -o gisutko.exe .
```

Модуль называется `gisutko`, поэтому `go build` без `-o` тоже даст `gisutko.exe`. Команда `go mod tidy` нужна только после изменения импортов.

Сборка Windows-версии из Linux/macOS (cgo не требуется):

```bash
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags="-s -w" -o gisutko.exe .
```

Флаги `-trimpath -ldflags="-s -w"` убирают отладочную информацию и локальные пути, уменьшая размер файла. На выходе — автономный `gisutko.exe` (~8 МБ), который достаточно скопировать пользователю.

## Использование

### Интерактивный режим

1. Положите `gisutko.exe` в папку с Excel-файлами.
2. Запустите двойным кликом.
3. Введите номер файла из списка.
4. Введите имя выходного JSON или нажмите Enter — будет использовано `<имя файла>.json`.
5. Файл сохранится в той же папке; окно закроется после нажатия Enter.

### Командная строка

```bash
gisutko.exe data.xlsx
gisutko.exe data.xlsx -o result.json
gisutko.exe data.xlsx -sheet "Лист1" -o result.json
gisutko.exe -all
```

Файл `.xlsx` можно перетащить мышью на `gisutko.exe`.

| Флаг | Описание |
|---|---|
| `-o <файл>` | имя выходного JSON; по умолчанию `<имя файла>.json`, расширение `.json` добавляется автоматически |
| `-sheet <имя>` | имя листа; по умолчанию используется первый лист книги |
| `-all` | обработать все `.xlsx` в папке с программой |

Код возврата: `0` — успешно, `1` — ошибка. Пригодно для запуска из скриптов и задач автоматизации.

В интерактивном и пакетном режимах файлы ищутся рядом с исполняемым файлом, а не в текущем каталоге запуска. Временные файлы Excel вида `~$имя.xlsx` игнорируются.

## Структура входной таблицы

Первые две строки — заголовки, они пропускаются. Данные читаются начиная с 3-й строки, соответствие колонок фиксированное.

### Данные населённого пункта

| Колонка | Содержимое |
|---|---|
| A | идентификатор населённого пункта |
| B | признак заполнения строки (учитывается при выборе названия) |
| C | название населённого пункта |
| D | широта |
| E | долгота |
| F | объём отходов |

Название берётся из колонки C при заполненной колонке B.

### Плечи маршрута

| Плечо | Колонки |
|---|---|
| 1 | G–O |
| 2 | P–X |
| 3 | Y–AG |

Каждое плечо занимает 9 колонок подряд:

| Смещение | Значение | Плечо 1 | Плечо 2 | Плечо 3 |
|---|---|---|---|---|
| +0 | идентификатор объекта | G | P | Y |
| +1 | тип объекта (текст) | H | Q | Z |
| +2 | мощность | I | R | AA |
| +3 | объём | J | S | AB |
| +4 | широта | K | T | AC |
| +5 | долгота | L | U | AD |
| +6 | расстояние | M | V | AE |
| +7 | тонно-километры | N | W | AF |
| +8 | скорость | O | X | AG |

### Типы объектов

| Значение в таблице | ObjectType |
|---|---|
| размещение | `DisposalObject` |
| обработка | `AssortmentObject` |
| обезвреживание | `IncinerationObject` |
| утилизация | `CompostingObject` |
| хранение | `StorageObject` |
| перегрузка | `TransshipmentObject` |
| другое или пусто | `UnknownObject` |

Сравнение выполняется по точному совпадению текста.

## Правила построения маршрута

1. Плечо 1 создаётся для каждой строки всегда; незаполненные числовые поля получают значение `0`.
2. Плечо 2 создаётся, только если заполнены все 9 его колонок; плечо 3 — по тому же правилу.
3. Плечо 3 вкладывается в плечо 2, плечо 2 — в плечо 1, плечо 1 — в запись населённого пункта. Если плеча 2 нет, плечо 3 в результат не попадает.
4. `TravelTime` вычисляется как `Distance / Speed` и округляется до 2 знаков (половины округляются к чётному). При нулевой или пустой скорости результат равен `0`.
5. Строка, в которой числовое поле содержит нечисловое значение, пропускается целиком с выводом сообщения `Ошибка в строке N`, где N — номер строки в Excel.
6. Пустые строки внутри таблицы дают запись с нулевыми значениями; пустые строки в конце таблицы отбрасываются.

## Формат результата

### Пример

```json
{
  "Routes": [
    {
      "PopulationId": "fa9b802a-b7e0-4cc1-a33e-589b0a4c6ee2",
      "PopulationName": "Сельское поселение Абанский сельсовет",
      "CountWaste": 2388.79,
      "Latitude": 56.67687,
      "Longitude": 96.066328,
      "Route": {
        "PartNumber": 1,
        "ObjectId": "8176d1b8-7ad0-4aad-a9ff-20570d181d25",
        "ObjectName": "1 Плечо",
        "ObjectType": "AssortmentObject",
        "Power": 114000.0,
        "Volume": 2388.79,
        "Latitude": 56.283958,
        "Longitude": 95.787375,
        "Polyline": null,
        "Distance": 90.66,
        "Tkm": 26.34888594749614,
        "TravelTime": 1.81,
        "Speed": 50.0,
        "Availability": 1,
        "TransportType": 1,
        "Route": {
          "PartNumber": 2,
          "ObjectId": "300977b4-4ca1-447c-97d1-e3ea7befc6b0",
          "ObjectName": "2 Плечо",
          "ObjectType": "DisposalObject",
          "Power": 114000.0,
          "Volume": 2030.471,
          "Latitude": 56.172466,
          "Longitude": 95.748776,
          "Polyline": null,
          "Distance": 12.8,
          "Tkm": 158.630546875,
          "TravelTime": 0.26,
          "Speed": 50.0,
          "Availability": 1,
          "TransportType": 1
        }
      }
    }
  ]
}
```

### Поля записи населённого пункта

| Поле | Тип | Источник |
|---|---|---|
| `PopulationId` | строка | колонка A |
| `PopulationName` | строка | колонка C при заполненной B |
| `CountWaste` | число | колонка F |
| `Latitude` | число | колонка D |
| `Longitude` | число | колонка E |
| `Route` | объект | плечо 1 |

### Поля плеча

| Поле | Тип | Источник |
|---|---|---|
| `PartNumber` | целое | номер плеча: 1, 2 или 3 |
| `ObjectId` | строка | идентификатор объекта |
| `ObjectName` | строка | `1 Плечо`, `2 Плечо`, `3 Плечо` |
| `ObjectType` | строка | значение из таблицы типов |
| `Power` | число | мощность |
| `Volume` | число | объём |
| `Latitude` | число | широта объекта |
| `Longitude` | число | долгота объекта |
| `Polyline` | null | всегда `null` |
| `Distance` | число | расстояние |
| `Tkm` | число | тонно-километры |
| `TravelTime` | число | `Distance / Speed`, 2 знака |
| `Speed` | число | скорость |
| `Availability` | целое | всегда `1` |
| `TransportType` | целое | всегда `1` |
| `Route` | объект | следующее плечо; у последнего плеча поле отсутствует |

### Правила вывода

- кодировка UTF-8 без BOM, кириллица не экранируется;
- отступ 2 пробела, порядок ключей фиксирован и приведён выше;
- целые числовые значения выводятся с дробной частью: `114000.0`, `50.0`;
- пустая ячейка даёт `0`, заполненная — число с полной точностью (`26.34888594749614`);
- значения от `1e16` и меньше `1e-4` выводятся в экспоненциальной записи (`1e+16`, `1.5e-07`);
- текстовые идентификаторы (UUID) сохраняются как есть; числовая ячейка идентификатора преобразуется в строку вида `12345.0`;
- перевод строки в конце файла не добавляется.

## Сообщения и диагностика

| Сообщение | Причина и решение |
|---|---|
| `В текущей папке нет Excel-файлов (.xlsx)` | рядом с программой нет `.xlsx`; положите файл в ту же папку или передайте путь аргументом |
| `Неверный выбор.` | введён номер вне диапазона списка или не число |
| `Ошибка в строке N: could not convert string to float: '...'` | в числовом поле текст; исправьте ячейку — строка N в Excel |
| `лист '...' не существует` | указано неверное имя в `-sheet`; проверьте название листа |
| `не удалось открыть '...'` | файл повреждён, имеет формат `.xls` или заблокирован другим процессом |
| не удаётся записать JSON | выходной файл открыт в другой программе или папка доступна только для чтения |

Русский текст в консоли Windows выводится корректно: программа сама переключает кодовую страницу в UTF-8.

## Структура проекта

| Файл | Назначение |
|---|---|
| `main.go` | чтение Excel, построение маршрутов, формирование JSON, интерфейс командной строки |
| `console_windows.go` | переключение консоли Windows в UTF-8 |
| `console_other.go` | реализация-заглушка для Linux/macOS |
| `go.mod`, `go.sum` | модуль `gisutko`, Go 1.27 и зафиксированные версии зависимостей (excelize v2.11.1) |

## Порядок работы программы

1. Открытие книги и выбор листа (по умолчанию первого).
2. Потоковое чтение строк с 3-й, получение точных значений ячеек.
3. Разбор колонок населённого пункта и трёх плеч по фиксированной раскладке.
4. Расчёт `TravelTime`, определение типов объектов, сборка вложенной структуры.
5. Сериализация в JSON и запись в файл с буферизацией.
